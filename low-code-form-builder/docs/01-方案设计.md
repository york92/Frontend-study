# 01 方案设计

## 1. 目标与范围

提供一个轻量、可扩展的低代码表单搭建器：**用 JSON Schema 描述表单，编辑器负责生成/修改 Schema，渲染器负责按 Schema 渲染并校验**。编辑与渲染共用同一套控件，保证“所见即所得”。

不在本版范围：真实后端、权限、版本管理、审批流、子表单与计算字段（见第 8 节路线图）。

## 2. 总体架构

```
┌────────────────────────── App.vue ──────────────────────────┐
│ Toolbar（表单切换 / 模式 / 设备 / 撤销重做 / 保存发布）        │
├──────────────┬──────────────────────────┬───────────────────┤
│ ComponentPanel│ Canvas ─ CanvasNode(递归) │ ConfigPanel       │
│ 组件库(拖拽源) │ 编辑区：拖放、选中、工具条 │ 字段/表单/事件配置 │
├──────────────┴──────────────────────────┴───────────────────┤
│ 预览模式：FormRenderer ─ RenderNode(递归)   JSON 模式：JsonView │
└──────────────────────────────────────────────────────────────┘
          │ 读写                         │ 纯函数
   store/builder.js (reactive)     schema/{registry,logic}.js
          │
      api/index.js ──► public/mockData.json（+ localStorage 持久化）
```

分层原则：
- **schema/**：无 UI 依赖的纯数据与逻辑（可单测、可复用到服务端校验）。
- **store/**：唯一的状态源与所有“编辑动作”，组件只调用动作、不直接改树。
- **components/**：展示与交互；`FieldControl` 是编辑区与渲染区共用的控件层。
- **api/**：数据访问边界，替换后端只改这一层。

## 3. 表单 Schema

```jsonc
{
  "id": "form_trip", "title": "员工出差申请表", "description": "…",
  "settings": { "labelPosition": "top|left", "submitText": "提交", "successMessage": "…" },
  "children": [ /* 节点树 */ ]
}
```

节点（Node）：

| 字段 | 说明 |
|---|---|
| `id` | 节点唯一 id（编辑器内部使用，复制时重新生成） |
| `type` | 组件类型，对应 `REGISTRY` 的 key |
| `props` | 组件属性（见下表） |
| `children` | 仅容器组件（row2 / row3 / card）有 |

常用 `props`：`label` `field`（数据键，需唯一）`placeholder` `defaultValue` `options: string[]` `min` `max` `required` `readonly` `rules`（`phone|email|url|""`）`width`（12 栅格：4=1/3，6=1/2，12=整行）`visibleWhen`（`{field, value}` 或 `null`）。

## 4. 关键设计决策

1. **12 栅格 + 子宽度**：所有容器按 12 列网格排布，字段用 `width` 占列数。两列/三列栅格容器的作用是让子节点默认宽度为 6/4；放入时由 `place()` 统一赋值，用户之后仍可在属性面板改。
2. **树形 Schema + 递归组件**：`CanvasNode`、`RenderNode` 递归渲染 `children`，天然支持任意层级嵌套。
3. **拖拽用原生 HTML5 DnD，不引入依赖**：拖拽状态放在 store（`state.dragging / state.over`），因为 `dragover` 阶段无法读取 `dataTransfer` 内容。放置规则：落在容器 → 追加到容器末尾；落在叶子节点 → 按鼠标位于前/后半区插入其前/后（行内小宽度节点按水平位置判断）。移动时会阻止把容器拖入自身子孙。
4. **撤销/重做 = 整树 JSON 快照**：简单可靠，最多 50 步；属性输入对同一节点同一属性 1 秒内合并为一步。
5. **显隐条件**：`visibleWhen = {field, value}`，以字符串比较（开关取值写 `true/false`）。隐藏的字段**不参与校验，也不会出现在提交数据中**。
6. **校验**：必填 + 规则（手机号/邮箱/网址）+ 数字范围，集中在 `schema/logic.js`，渲染器提交时调用。
7. **响应式预览**：舞台宽度切换 + CSS Container Query（≤480px 时所有字段整行），因此“手机”预览与真实窄屏一致。

## 5. 数据流

```
用户操作 ─► store 动作(snapshot → 修改 form 树) ─► Vue 响应式 ─► Canvas/ConfigPanel 刷新
保存 ─► api.saveForm ─► localStorage(Mock DB)
预览提交 ─► logic.validate ─► logic.collect ─► api.submitForm ─► 回显结果
```

## 6. Mock 后端

- 数据源 `public/mockData.json`：`forms[]`（含 `schema`）与 `submissions[]`。
- 首次启动读取该文件并写入 `localStorage`（键 `lowcode-form-builder:mock-db`）；后续读写都走 localStorage，以便“保存/发布/提交”能在刷新后保留。
- 顶栏“重置 Mock”清除 localStorage，恢复为 JSON 文件初始内容。
- 接口约定（`src/api/index.js`）：`listForms / getForm / createForm / saveForm / publishForm / submitForm / listSubmissions`。

对接真实后端：保持函数签名，把函数体换成 `fetch('/api/…')` 即可，其它层无需改动。建议 REST 映射：
`GET /forms`、`GET /forms/:id`、`POST /forms`、`PUT /forms/:id`、`POST /forms/:id/publish`、`POST /forms/:id/submissions`。

## 7. 扩展指南

**新增控件**（如“时间选择”）：
1. `schema/registry.js` 的 `REGISTRY` 增加一项（类型、图标、可配置项 `config`、默认属性）。
2. `components/FieldControl.vue` 增加对应渲染分支。
3. 如需特殊初始值/校验，在 `schema/logic.js` 补充。
组件库面板、属性面板、渲染器、JSON 导入导出均自动生效。

**新增属性配置项**：在 `ConfigPanel.vue` 的 `F` 表中登记（类型 `text|number|seg|lines|switch|rules|cond`），再把 key 加进组件的 `config` 数组。

**新增校验规则**：在 `logic.js` 的 `RULES` 增加正则与提示，并在 `ConfigPanel.vue` 的 `RULE_OPTS` 增加选项。
